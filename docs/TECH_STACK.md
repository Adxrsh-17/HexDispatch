# Tech Stack

Each choice: why, and what was rejected. Changing any of these requires an ADR (see [adr/0001-tech-stack.md](adr/0001-tech-stack.md)).

| Concern                  | Choice                                             | Reason                                                                              | Rejected                                                                              |
| ------------------------ | -------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Language                 | TypeScript, strict                                 | One language across services, simulator and shared code; types catch contract drift | Go (second language, cannot share `packages/matching` with the simulator)             |
| Runtime                  | Node >= 22                                         | LTS line with native `--env-file`, stable `fetch`, good perf                        | Node 20 (older), Bun/Deno (ecosystem risk for Testcontainers, kafkajs)                |
| Package manager          | pnpm workspaces                                    | Fast, strict dependency graph, simple workspaces                                    | npm/yarn workspaces (looser hoisting), Nx/Turborepo (not needed at this size)         |
| Modules                  | ESM                                                | Modern default; matches tsx and Vitest                                              | CommonJS                                                                              |
| Dev runner               | tsx                                                | Runs TS source directly, no build step in dev                                       | ts-node (slower, ESM friction)                                                        |
| HTTP                     | Fastify 5                                          | Fast, schema-first, first-class logging with pino, plugin system                    | Express (slower, weaker typing), NestJS (heavy for a showcase of algorithms)          |
| Validation               | zod                                                | One schema gives types and runtime checks; shared with Kafka events                 | JSON Schema + ajv alone (no TS inference), io-ts                                      |
| WebSocket                | @fastify/websocket                                 | Plain WebSockets with a small protocol, same server lifecycle                       | Socket.IO (extra protocol, harder multi-node story)                                   |
| Database                 | PostgreSQL 16                                      | Transactions for trips, outbox and ledger; one engine to operate                    | MongoDB (weak multi-document transactions for money), MySQL                           |
| ORM / migrations         | Drizzle + drizzle-kit                              | SQL-like, light, type-safe, explicit migrations                                     | Prisma (heavier runtime, generated client), TypeORM (decorators, magic)               |
| Data isolation           | Schema per service (separate databases)            | Enforces service boundaries; no cross-service joins                                 | One shared schema (hidden coupling)                                                   |
| Cache / index            | Redis 7 + ioredis                                  | H3 cell sets, driver hashes, Lua for atomic claims, pub/sub for fan-out             | In-process maps (no sharing across nodes), PostGIS (too slow for 3-5 s pings)         |
| Messaging                | Kafka API via Redpanda + kafkajs                   | Per-key ordering, replay, consumer groups; Redpanda is a single light container     | RabbitMQ (no log replay or key ordering), real Kafka+ZooKeeper (heavy locally)        |
| Geo                      | h3-js                                              | Hexagonal cells, uniform neighbours, k-ring, parent/child for sharding              | Geohash (uneven neighbours), S2 (less JS support), Redis GEO alone (no sharding unit) |
| Logging                  | pino                                               | Fastest structured logger, native in Fastify                                        | winston (slower)                                                                      |
| Metrics                  | prom-client + Prometheus                           | De-facto standard; Grafana dashboards                                               | StatsD, vendor agents                                                                 |
| Tracing                  | OpenTelemetry                                      | Vendor-neutral traces across HTTP and Kafka                                         | Vendor SDKs                                                                           |
| Dashboards               | Grafana                                            | Standard with Prometheus                                                            | Custom UI                                                                             |
| Unit / integration tests | Vitest + Testcontainers                            | Fast TS-native runner; real Postgres/Redis/Redpanda in tests instead of mocks       | Jest (slower with ESM), mocked databases (hide real bugs)                             |
| Load tests               | k6                                                 | Scriptable, good percentiles, WebSocket support                                     | Artillery, JMeter                                                                     |
| Lint / format            | ESLint 9 flat config + typescript-eslint, Prettier | Standard, low friction                                                              | Biome (smaller ecosystem for TS rules today)                                          |
| CI                       | GitHub Actions                                     | Where the repo lives; Docker available for Testcontainers                           | Self-hosted runners                                                                   |
| Local infra              | Docker Compose                                     | One command for all dependencies                                                    | Kubernetes (optional later, out of scope)                                             |

Not installed yet (arrive with the phase that needs them): ioredis, kafkajs, h3-js, drizzle-orm, drizzle-kit, pg, @fastify/websocket, OpenTelemetry packages, testcontainers, k6 scripts beyond a smoke test.
